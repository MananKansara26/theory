The important Kafka components are:
Producer → sends messages
Topic → category where messages are stored
Partition → divides a topic for scalability
Broker → Kafka server that stores messages
Consumer → reads messages
Consumer Group → group of consumers working together
Offset → position of a message in a partition


A topic is like a named container/category for messages.
orders
payments
notifications
user-events
Above are topics

A topic can be divided into partitions. Why? Scalability.
orders topic
Partition 0:  [M1] [M4] [M7] [M10]
Partition 1:  [M2] [M5] [M8] [M11]
Partition 2:  [M3] [M6] [M9] [M12]
Partition = smaller pieces of a topic

Suppose you have 1 million messages.
Instead of one Kafka server/process handling everything:
1 partition
     ↓
1 million messages
you can distribute them:
Partition 0 → 330k
Partition 1 → 330k
Partition 2 → 340k

Broker = physical/server machine
Partition = data unit stored on that machine



Consumer pulls from whom?

The consumer pulls messages from a partition.
But technically it communicates with the broker that is hosting that partition.

Partition 0
    ↓
Broker 1

Consumer asks Broker 1: "Give me messages from Partition 0 starting from offset 100."

Broker 1 sends them.

Consumer
    │
    │ Give me messages
    ↓
Broker 1
    │
    ↓
Partition 0
So the consumer does not randomly ask brokers: ❌ Consumer → Give me any job
Instead: ✅ Consumer → I need messages from my assigned partition

But who decides which partition the consumer reads?
Consumer Group + Kafka's partition assignment mechanism.

Kafka stores each partition as an append-only log on the broker's disk.
